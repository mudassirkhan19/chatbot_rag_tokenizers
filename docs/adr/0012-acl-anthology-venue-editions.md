# 0012. ACL Anthology venue Editions

- **Date:** 2026-10-16
- **Status:** Accepted. A volume ID counts as no paper ([0017](0017-acl-volume-ids-count-as-no-paper.md)).

## Context
Issue #6 asks for every Work with an ACL Anthology Edition to get a venue row of its own, with its venue, year, licence and PDF link taken from the Anthology. The dedup stage needs real preprint vs. venue duplicates to detect and measure, so the venue row must never be merged into the preprint. They may share only the external identifiers the sources recorded. After [0008](0008-semantic-scholar-keyword-discovery.md), a Semantic Scholar record with an arXiv ID becomes the preprint row and keeps the ACL ID only as an identifier. That leaves the venue Edition of most ACL papers that are also on arXiv (SentencePiece, Sennrich et al.'s subword NMT paper) without a row.

The Anthology has no query API. Its [data-access FAQ](https://aclanthology.org/faq/api/) points to the `data/xml` files in its GitHub repository and to the `acl-anthology` Python package, which reads those files. Each file holds a whole collection, though: `2024.findings.xml` is 5.7 MB, and `W19.xml` covers every 2019 workshop. The live Semantic Scholar pages report 178 ACL IDs from 102 collections, so storing the collection files would put hundreds of MB in the Snapshot. The per-paper exports are small, but they're incomplete: `<id>.bib` and `<id>.xml` (MODS) have no abstract, no venue name and no PDF link. The paper page `https://aclanthology.org/<id>/` has all of them. Its `citation_*` meta tags (the Highwire tags the Anthology publishes for scholarly indexers) give the title, authors, DOI and PDF link. Its details list gives the year, the venue(s) and the publisher, and its abstract card gives the abstract when there is one.

Licences, from the [copyright FAQ](https://aclanthology.org/faq/copyright/), cover ACL materials only. Those published before 2016 are CC BY-NC-SA 3.0, and those published in or after 2016 are CC BY 4.0. Third-party material (for example LREC, published by ELRA, or TACL, published by MIT Press) isn't covered.

## Decision
- **Which ACL IDs:** every ACL ID a source reported for any Edition. That is the `acl_id` field, or else a DOI of the form `10.18653/v1/<ACL ID>`, which ACL mints from the ACL ID (arXiv reports such DOIs on preprints). Sources disagree on a DOI's case, so an ACL ID read from a DOI takes the Anthology's own case: upper-case for old-style IDs (`P16-1162`), lower-case for new-style ones (`2020.findings-emnlp.414`). The pages are fetched right after discovery, before the rule pre-filter, because the venue row's own Relevance verdict depends on what the page says. So unlike arXiv records ([0010](0010-arxiv-records-for-rule-passes-only.md)), a page is fetched even when the preprint that reported the ACL ID is rule-rejected.
- **One paper page per ACL ID**, `GET https://aclanthology.org/<id>/`, stored in the Snapshot under `responses/acl-anthology/` with the request description `{"source": "acl-anthology", "url": …, "params": {}}`. A 404 is stored as an empty body, so a source's wrong ACL ID is remembered and a replay stays offline. This narrows [0006](0006-arxiv-records-via-oai-pmh.md)'s rule that error responses are never stored: a 404 here is a permanent answer about the ID, not a glitch. Any other error, or a page that isn't the paper page for that ID, stops the run before anything is stored. The Anthology publishes no rate limit, so we wait 1 s between requests.
- **The Anthology is the authority for its Edition.** If a source already found the venue Edition (under its ACL ID, or under the DOI the Anthology reports, as long as that row names no other ACL ID), that row is updated in place. Otherwise a new venue row is added. Either way the row is named by its ACL ID, and its title, authors, year, venue, DOI, licence, `source_link` (`https://aclanthology.org/<id>`) and `pdf_link` come from the page. A Semantic Scholar paperId already on the row is kept. A new row gets no `s2_id` and no `arxiv_id`: those identify the preprint record that reported the ACL ID, and the s2 id is a match key, so copying it would merge the two Editions on a later combine.
- **Venue** is the Anthology's venue name, for example "Annual Meeting of the Association for Computational Linguistics", which is the same form Semantic Scholar uses. When a volume belongs to several venues (LREC-COLING), the names are joined with `|`. The volume title ("Proceedings of the 54th Annual Meeting …") isn't recorded.
- **Licence:** CC BY 4.0 (`https://creativecommons.org/licenses/by/4.0/`) when the publisher is the Association for Computational Linguistics (two volumes spell it "Lingustics", which counts too) and the year is 2016 or later, CC BY-NC-SA 3.0 when the year is before 2016, and `unknown` for any other publisher.
- **`pdf_link`** is a new manifest column. It holds the Anthology's PDF URL, and stays empty for other Editions until the fetcher (#10) needs it.
- **Abstract:** the Anthology's, where it has one. Many older papers have none (P16-1162, for one), and then the rules and the judge would see only the title. In that case the abstract that the reporting source gave alongside the ACL ID is used, since it describes the same Work. The manifest doesn't show the abstract, so this only affects the Relevance verdict.
- **Discovery channels:** the venue row lists every channel whose Candidates reported its ACL ID, plus any channel that found it directly. The keyword query that found SentencePiece's preprint did, in effect, find its EMNLP Edition, so the channel counts in the report include linked venue Editions.

## Alternatives considered
- **The repository's `data/xml` collection files, or the `acl-anthology` package:** these are the authoritative source and include the abstracts, but they cost a whole collection per paper. That would mean hundreds of MB in the Snapshot, against the roughly 10 kB compressed per paper page.
- **`<id>.bib` or MODS per paper:** an official export format, but with no abstract, no venue name and no PDF link. We would need a second request per paper for those anyway.
- **The bulk `anthology+abstracts.bib.gz`:** one request, but tens of MB. It would also change as a whole on every Anthology build, so it couldn't be pinned per paper.
- **Merging the ACL Edition into the preprint, or taking its metadata from Semantic Scholar:** this would hide the duplicate the dedup stage has to measure. Semantic Scholar's record also mixes the preprint's and the venue Edition's fields (see 0008).
- **A separate `acl-anthology` Discovery channel:** the Anthology isn't searched, it is only looked up. Crediting the query that reported the ACL ID keeps channels meaning "the route by which a Candidate was found".
- **Prior work (research-bot):** it queries arXiv only and records no venue Editions or licences.

## Consequences
- On the first live run, with the keyword queries from before #4's full query set and Seeds, discovery's 4,285 Editions reported 199 ACL IDs (some only as ACL DOIs on arXiv preprints). Two of them (`2020.webnlg-papers.5` and `.22`) aren't in the Anthology. The other 197 updated 90 Semantic Scholar venue rows and added 107 new venue Editions, giving 4,392 Editions. 148 of the ACL Editions are CC BY 4.0 and 49 are `unknown` (LREC, AMTA, EAMT, COLING, TACL and others). None of them is from before 2016. The pages took about 4 minutes to fetch at 1 s each and add 2 MB to the Snapshot. The full query set and citation expansion report more ACL IDs, and the next full run fetches their pages.
- Parsing HTML ties us to the page layout. The `citation_*` tags are a published convention for indexers, but the details list and the abstract card aren't. A layout change makes the stored-page check fail loudly instead of writing empty fields.
- A Semantic Scholar venue row that was named by its DOI or paperId is renamed to its ACL ID, so any verdict cached under the old id is no longer found and the row is scored again. The cache is keyed by Edition id, model, revision and prompt ([0007](0007-local-llm-judge.md)), not by the abstract, so a borrowed abstract that changes later doesn't invalidate a verdict.
- Pre-2016 papers without an abstract are judged on another source's abstract for the same Work. If the reporting source had no abstract either, the row is judged on its title alone.
- ACL Editions whose only identifiers are a non-ACL DOI and no ACL ID (some TACL records in Semantic Scholar) stay Semantic Scholar venue rows until some source reports their ACL ID.
